# personafactory.persona_bank

Builds the PersonaFactory persona bank: 743,010 structured synthetic user profiles over 177 countries and 599
(country, sub-region) locations. Each profile has a background layer (who the person is) and a style layer (how
they type to a chat assistant). Profiles are generated by three open LLMs, screened by an independent LLM judge
with two-pass repair, and deduplicated by a diversity filter. The same style layer can be added to existing
persona sets (style extension, last section).

| generator | profiles |
|---|---|
| `google/gemma-4-31B-it` | 254,247 |
| `mistralai/Ministral-3-14B-Instruct-2512` | 247,680 |
| `zai-org/GLM-4.7-Flash` | 241,083 |

Judge: `MiniMaxAI/MiniMax-M2.5` (not a generator, so no self-preference). Embeddings of the diversity filter:
`intfloat/multilingual-e5-large`.

Run every command from the repository root as `python -m personafactory.persona_bank.<module>`; each module has
`--help`. Model calls go to OpenAI-compatible endpoints (vLLM or SGLang); an API key, if needed, is read from
`PF_API_KEY`. `scripts/examples/persona_bank.sh` submits the whole pipeline with the exact settings below, using
the generic Slurm templates `scripts/slurm/persona_bank_*` (cluster flags on the `sbatch` command line or in
`SBATCH_ARGS`, environment activation in `ENV_SETUP`, model weights from `PF_MODEL_DIR`).

## Seed grids

The sampler draws every seeded attribute in code; the generator fills the rest of the profile around them.

| | base grid (`generate_bank.py`) | extended grid (`grid_extended.py`) |
|---|---|---|
| locations | 201 in 81 countries, 13 macro-regions | 599 in 177 countries (the 201 base locations first) |
| occupations | 211 in 16 sectors, weighted by sector AI-usage propensity | 575 in 23 sectors (the 211 base ones first), fixed sector shares |
| per-location target | coverage x region weight x sub-region scale | per-country quotas: 13 target-block shares, sqrt(population) within a block, country floors and a 4% cap |
| other seeds | gender (country-conditioned), age (occupation-aware), AI stance, digital fluency (sector-coherent) | same, with occupation-specific age ranges and fluency overrides |
| additional seed axes | none | settlement type, education level, life stage, home language (303 multilingual locations), typing style (one canonical value per structured key) |
| schema | `schema.Persona` | `schema.PersonaExtended` (adds `settlement_type`, `life_stage`) |

Occupations are sampled independently of region; only physically place-bound jobs are gated (no deep-sea fisher
in a landlocked country). Seeded fields are written back after generation, so the model cannot change them. On
the extended grid a profile is rejected (and retried once) if more than one of the seven structured typing keys
differs from the typing-style seed, or if fewer than two linguistic quirks of at least three words remain.

## Pipeline

| step | module | input | output |
|---|---|---|---|
| 1. generate | `generate_bank.py` | seed grid + generator endpoint | `persona_bank_<model>.shardIIofNN.jsonl` (+ `.attempts.jsonl` call log) |
| 2a. merge (base grid) | `merge_shards.py` | generator shards | `persona_bank_all.jsonl` |
| 2b. merge and split (extended grid) | `judge_shards.py split` | generator shards | `raw_all.jsonl`, `judge_in/shard_XXXX.jsonl` |
| 3. judge + repair | `validate_personas.py` | merged bank or judge shards | `*.validated.shardIIofNN.jsonl` or `judge_out/val_XXXX.jsonl` |
| 4a. keep-only bank (base grid) | `finalize_bank.py` | validated shards | `persona_bank_all.validated.jsonl`, `persona_bank_all.clean.jsonl` |
| 4b. merge judged (extended grid) | `judge_shards.py merge`, then `strip_surrogates.py` | `judge_out/val_*.jsonl` | `validated_all.jsonl` |
| 5. emoji rebalancing (base grid) | `rebalance_emoji.py fix`, then `repair` | clean bank | `persona_bank.jsonl`, `persona_emoji_changes.jsonl` |
| 6. diversity filter (extended grid) | `diversity_filter.py` | `validated_all.jsonl` + reference bank(s) | `kept.jsonl`, `dropped.jsonl`, `report.json` |
| 7. assemble | `assemble_bank.py` | base bank + kept extended profiles | `persona_bank.jsonl`, report |

Steps 1 and 3 call model servers; steps 5 (Gemma 4 31B offline with vLLM, TP4) and 6 (one GPU) run on GPU nodes;
the rest is CPU. Generation and judging are resumable: a relaunched shard fills its remaining per-location deficit
or skips profiles already judged.

The released bank combines three generation sets that share the generators, the judge and the filter settings:

| set | grid and targets | seed axes | generated | judge keep | kept |
|---|---|---|---|---|---|
| base | base grid, coverage 88 | none | 102,520 | 99,696 | 99,696 (after emoji rebalancing) |
| extended | extended grid, 590,000 raw over all 13 target blocks | all five | 584,294 | 556,327 | 546,547 |
| extended, Europe + Southeast Asia | extended grid, 110,000 raw: 55,000 for the four European blocks, 55,000 for Southeast Asia | education, home language, typing style | 108,929 | 104,079 | 96,767 |

Total 795,743 generated, 743,010 released.

## Settings used for the release

### 1. Generation

| set | generator | shards | seed of shard i | temperature | sharding | max tokens |
|---|---|---|---|---|---|---|
| base | Gemma / Ministral / GLM | 80 each | 1000+i / 2000+i / 3000+i | 0.8 | by location | 8000 |
| extended | Gemma | 1920 | 31000+i | 0.9 | by slot | 4096 |
| | Ministral | 1152 | 32000+i | 0.8 | by slot | 4096 |
| | GLM | 1536 | 33000+i | 0.8 | by slot | 4096 |
| extended, Europe + SEA | Gemma | 384 | 31500+i | 0.9 | by slot | 4096 |
| | Ministral | 384 | 32500+i | 0.8 | by slot | 4096 |
| | GLM | 288 | 33500+i | 0.8 | by slot | 4096 |

```bash
# base grid, one shard (i = 0..79; Ministral seed 2000+i, GLM seed 3000+i)
python -m personafactory.persona_bank.generate_bank --model_name google/gemma-4-31B-it \
    --base_url http://HOST:8000/v1 --coverage_per_location 88 \
    --shard_count 80 --shard_index $i --seed $((1000 + i)) --output_dir $PF_DATA_DIR/persona_bank/base
# extended grid, all blocks, one Gemma shard (i = 0..1919)
python -m personafactory.persona_bank.generate_bank --grid extended --model_name google/gemma-4-31B-it \
    --base_url http://HOST:8000/v1 --target_total 590000 --n_generators 3 --shard_by slot \
    --shard_count 1920 --shard_index $i --seed $((31000 + i)) --temperature 0.9 \
    --output_dir $PF_DATA_DIR/persona_bank/extended/raw
# extended grid, Europe + Southeast Asia, one Gemma shard (i = 0..383)
python -m personafactory.persona_bank.generate_bank --grid extended --model_name google/gemma-4-31B-it \
    --base_url http://HOST:8000/v1 --target_total 110000 --n_generators 3 --shard_by slot \
    --block_totals Europe:55000,Southeast_Asia:55000 --seed_axes education,home_language,style \
    --shard_count 384 --shard_index $i --seed $((31500 + i)) --temperature 0.9 \
    --output_dir $PF_DATA_DIR/persona_bank/extended_eu_sea/raw
```

Serve each generator under its Hugging Face id (`generator_model` stores `--model_name`). With
`--target_total` on the extended grid, each generator fills its own third of every location target
(`--generator_index`, default: Gemma 0, Ministral 1, GLM 2). Each process is sequential; throughput scales with the
number of shards per server replica (`scripts/slurm/persona_bank_generate.sbatch` runs all shards of a generator
over the nodes of one job).

### 2-4. Judge with two-pass repair

The judge scores internal coherence, occupation / location plausibility, LLM-user plausibility, stereotype
severity (0-3) and realism (0-3), and may return repairs: a corrected `digital_fluency`, a concise `job_title`,
and corrected `reference_pool` / `linguistic_quirks` lists. Repairs are applied and the repaired profile is judged
again for the final verdict. A profile is rejected if it is incoherent, implausible for its location or as an LLM
user, or has stereotype severity >= 2; parse failures are `unscored` and never count as a pass.

| set | shards | max tokens | merged with |
|---|---|---|---|
| base | 120 strided shards of `persona_bank_all.jsonl` | 1600 | `finalize_bank.py` |
| extended | 2304 (`judge_shards.py split --nsh 2304`) | 3072 | `judge_shards.py merge` |
| extended, Europe + SEA | 768 | 3072 | `judge_shards.py merge` |

```bash
python -m personafactory.persona_bank.merge_shards --data-dir $PF_DATA_DIR/persona_bank/base
python -m personafactory.persona_bank.validate_personas --input .../base/persona_bank_all.jsonl \
    --output .../base/persona_bank_all.validated.jsonl --judge-model MiniMaxAI/MiniMax-M2.5 \
    --base-url http://HOST:30000/v1 --shard_count 120 --shard_index $i --max_tokens 1600
python -m personafactory.persona_bank.finalize_bank --validated .../base/persona_bank_all.validated.jsonl \
    --clean .../base/persona_bank_all.clean.jsonl

python -m personafactory.persona_bank.judge_shards split --raw_dir .../extended/raw \
    --raw_all .../extended/raw_all.jsonl --judge_in .../extended/judge_in --nsh 2304
python -m personafactory.persona_bank.validate_personas --input .../extended/judge_in/shard_0000.jsonl \
    --output .../extended/judge_out/val_0000.jsonl --judge-model MiniMaxAI/MiniMax-M2.5 --base-url http://HOST:30000/v1
python -m personafactory.persona_bank.judge_shards merge --judge_out .../extended/judge_out \
    --out .../extended/validated_all.jsonl
python -m personafactory.persona_bank.strip_surrogates .../extended/validated_all.jsonl
```

`strip_surrogates.py` replaces lone UTF-16 surrogates (broken emoji in a handful of generated profiles) with
U+FFFD. `--concurrency N` judges N profiles in parallel per process (same results).

### 5. Emoji rebalancing (base grid)

Frequent decorative emoji would dominate the rewritten turns, so only 5% of the base-grid bank keeps
`emoji_use: frequent/decorative` (fixed hash ranking, salt `emoji-keep:`); the other frequent-emoji profiles are
set to `none` and every emoji mention in their profile text is minimally rewritten by Gemma 4 31B. Of 21,447
frequent profiles, 4,985 kept and 16,462 were downgraded. The extended grid samples the typing style with
frequent/decorative emoji at 5% already, so its profiles skip this step.

```bash
python -m personafactory.persona_bank.rebalance_emoji fix --bank .../base/persona_bank_all.clean.jsonl \
    --out .../base/persona_bank.jsonl --log .../base/persona_emoji_changes.jsonl --model google/gemma-4-31B-it
python -m personafactory.persona_bank.rebalance_emoji repair --orig .../base/persona_bank_all.clean.jsonl \
    --bank .../base/persona_bank.jsonl --log .../base/persona_emoji_changes.jsonl --model google/gemma-4-31B-it
```

### 6. Diversity filter (extended grid)

Greedy, best profiles first (judge realism, then stereotype severity, then a salted hash). A candidate is dropped
if its description or example message duplicates a kept one (after normalization), if its cell is full (12 per
location x occupation, 2 per location x occupation x gender x age bin x AI stance x fluency, 3% of the output per
canonical 7-key typing-style combination), or if its description cosine to a kept profile exceeds 0.96, or both
description and style cosines exceed 0.95. Reference banks are always kept and count toward every cap. All
thresholds are the defaults.

| set | reference | dropped (cell cap / full-cell cap / near-dup joint / near-dup description / exact dups) |
|---|---|---|
| extended | base-grid bank | 5,915 / 834 / 1,680 / 1,103 / 248 |
| extended, Europe + SEA | base-grid bank + kept extended profiles | 6,337 / 518 / 268 / 146 / 43 |

```bash
python -m personafactory.persona_bank.diversity_filter --input .../extended/validated_all.jsonl \
    --reference .../base/persona_bank.jsonl --output .../extended/diversity/kept.jsonl \
    --dropped .../extended/diversity/dropped.jsonl --report .../extended/diversity/report.json \
    --emb_cache .../extended/diversity/emb
python -m personafactory.persona_bank.diversity_filter --input .../extended_eu_sea/validated_all.jsonl \
    --reference .../base/persona_bank.jsonl .../extended/diversity/kept.jsonl \
    --output .../extended_eu_sea/diversity/kept.jsonl --dropped .../extended_eu_sea/diversity/dropped.jsonl \
    --report .../extended_eu_sea/diversity/report.json --emb_cache .../extended_eu_sea/diversity/emb
```

### 7. Assemble

```bash
python -m personafactory.persona_bank.assemble_bank --base .../base/persona_bank.jsonl \
    --part .../extended/diversity/kept.jsonl --part .../extended_eu_sea/diversity/kept.jsonl \
    --dropped .../extended/diversity/dropped.jsonl --dropped .../extended_eu_sea/diversity/dropped.jsonl \
    --out $PF_DATA_DIR/persona_bank.jsonl --report $PF_DATA_DIR/persona_bank_report.json
```

The base-grid profiles come first, then the two kept sets in this order. The seeded `settlement_type` and
`life_stage` fields (and their `gen_meta.seed_axes` copies) are not part of the released schema and are removed.

## Output schema (`schema.py`)

One JSON object per line:

- `id`, `generator_model`, `character_description` (3-5 sentences, no typing behaviour)
- `background`: `region`, `country`, `sub_region`, `occupation`, `sector`, `job_title`,
  `education` {`level`, `field_of_study`, `institution_type`}, `age` (18-80), `main_language` (canonical name),
  `native_language`, `dialect` (short label), `hobbies_interests`, `gender`, `ai_stance`, `digital_fluency`,
  `llm_user_segment` (`core` | `underrepresented` for low fluency)
- `style`: `sentence_length_tendency`, `question_framing`, `native_language_error_patterns`,
  `code_switching_freq`, `code_switching_type`, `reference_pool`, `chatting_style` (one free-text sentence),
  `chatting_style_structured` {`capitalization`, `punctuation`, `emoji_use`, `abbreviation_habits`,
  `message_structure`, `typo_tendency`, `greeting_signoff`}, `example_message`, `chatbot_language_pref`,
  `linguistic_quirks` (2-4)
- `gen_meta`: `temperature`, `seed`, `coverage_target` (base grid: the coverage; extended grid:
  `quota:<target_total>/g<generator index>:<location target>`); extended grid also `grid`, `seed_axes` (the
  sampled seeds), `style_seed_mismatch`, `home_language_followed`, `attempts`, `reject_reasons`,
  `prompt_tokens`, `completion_tokens`, `t_done`
- `validation`: verdict, scores, reason, requested fixes, `*_repaired` {from, to} records, `judge_meta`
  (extended grid: calls, tokens, truncations, first-pass verdict); base grid also `emoji_downgrade` where step 5
  edited the profile

The docstring of `schema.ChattingStyle` becomes the `description` of that object in the JSON schema embedded in
the generation prompt, so it is kept verbatim; `schema.json_schema()` returns the schema exactly as embedded.

## Style extension of existing persona sets (`extend_style.py`)

Adds the style layer to persona sets that describe who a person is but not how they write. Each source record
becomes one bank-format profile: the background is a faithful English conversion of the source, the style layer is
generated with the same rules as the bank prompt (`generate_bank.style_layer_rules`, typing-style seed from
`grid_extended.sample_style_seed`, schema `PersonaExtended`), and the source record is kept under `source`.

- Sources: the 12 Nemotron-Personas country releases (`nvidia/Nemotron-Personas-<Country>`, adults only) and
  `proj-persona/PersonaHub`, read from the local Hugging Face cache (`--hf_cache`, default `$HF_HOME/hub`).
- Pinned from the source: age, gender, country, region and main language (Nemotron-Personas); PersonaHub
  personas stay English and the model infers the rest.
- Digital fluency is inferred from the source in a first short call, then enforced; the typing-style seed is
  conditioned on it. Caseless scripts get `capitalization: Standard`.
- Generator: Gemma 4 31B, temperature 0.8. The output is judged like the bank (`validate_personas.py`).

| stage | command | output |
|---|---|---|
| sample sources | `extend_style prep --out RUN --per_country 160 --personahub 220` | `RUN/sources.jsonl` (2,140 records) |
| generate | `extend_style gen --out RUN --base_url URL --shard_count 16 --shard_index i --concurrency 48` | `RUN/gen/shard_XXXX.jsonl` |
| collect | `extend_style collect --out RUN` | `RUN/raw/persona_bank_extend.jsonl`, `RUN/gen_summary.json` |
| judge | `judge_shards split --nsh 8`, `validate_personas --concurrency 32`, `judge_shards merge` | `RUN/judge_out/val_XXXX.jsonl` |

Slurm: `scripts/slurm/style_extension_generate.sbatch`, then `persona_bank_judge.sbatch` with `RUN` set to the
same directory. The A/B evaluation of the extended personas (raw source record vs converted background vs
background with style layer, three judges) is in `personafactory/evaluation/style_extension/`; the full chain is
`scripts/examples/style_extension.sh`.

## Dependencies

`openai`, `pydantic` (v2) for generation and judging; `torch`, `transformers`, `numpy` for the diversity filter;
`vllm` for emoji rebalancing; `pyarrow` for the style-extension sources; `python-dotenv` optional (reads a local
`.env`).
