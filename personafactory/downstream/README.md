# personafactory.downstream

Fine-tuning experiments on the released corpus (paper appendix "Downstream Fine-tuning on the Released Corpus",
tables `tab:downstream-clean`, `tab:downstream-paired`, `tab:downstream-x`): what do the released conversations, with
their persona-styled user turns, do for a model trained on them, and which part of the pipeline is responsible?

Every module runs as `python -m personafactory.downstream.<module>` and has `--help`. Inputs are the published
dataset ([`swiss-ai/PersonaFactory`](https://huggingface.co/datasets/swiss-ai/PersonaFactory), subsets `chats` and
`persona_bank`; a hub id, a local snapshot, parquet files, or a pipeline release directory all work) and the public
seed datasets. Paths come from arguments or `PF_DATA_DIR`, `PF_OUT_DIR`, `PF_BANK`, `PF_LID_MODEL`, `PF_MODEL_DIR`;
endpoints from arguments or `PF_GEMMA_URL`, `PF_MINISTRAL_URL`, `PF_MINIMAX_URL`, `PF_JUDGE_URLS`; API keys from
`PF_API_KEY` (any value for local servers). `scripts/examples/downstream.sh` runs the stages below; the Slurm
templates are `scripts/slurm/downstream_*` and `scripts/slurm/eval_*` (cluster flags on the `sbatch` command line or
in `SBATCH_ARGS`, environment activation in `ENV_SETUP`, containers in `SRUN_ARGS`).

## Arms

Language-matched (all four on the same 79,817 conversations, 5% of the personas held out for evaluation):

| Arm | User turns | Assistant turns | Built by |
|---|---|---|---|
| A0 | original seed | original seed | `build_arms.py` |
| A0r | original seed | regenerated by the same responder, no persona, same continuity loop and sanity gate | `a0r.py` |
| A1 | persona-styled (released) | original seed | `build_arms.py` |
| A2 | persona-styled (released) | regenerated for that user (released) | `assemble_arms.py` |

Cross-lingual (40,528 conversations, same English seeds and target personas in both arms):

| Arm | User turns | Assistant turns | Built by |
|---|---|---|---|
| X1 | seed turns translated into the persona's language by the pipeline's persona-blind translation step | regenerated without a persona, as A0r | `x_arms.py` |
| X2 | released (translated, then restyled) | released | `x_arms.py` |

A conversation is removed from all arms of its group if its A0r (or X1) regeneration fails the sanity gate or any
arm exceeds 3,800 tokens (Apertus tokenizer, contents plus 10 tokens per turn), so every document fits the
4,096-token packing window.

## Steps

### 1. Seeds (`seeds.py`)

A0, A1 and X1 need the seed conversation. Released conversations keep `source_id` (`wildchat:<hash>:<turn id>`,
`ultrachat:<id>`, `nemotron:<uuid>`) and the seed's first user turn (`original_prompt`). `seeds.py` resolves them from
the pipeline's seed records (`--seed-shards`, exact) or from the public seed datasets (`--source`, default
`allenai/WildChat-4.8M`, `stingning/ultrachat`, `nvidia/Nemotron-Instruction-Following-Chat-v1`), normalized like the
pipeline seeds (first 3 user turns with their replies, empty leading system turn dropped, reasoning removed from
Nemotron replies).

```bash
W=$PF_OUT_DIR/downstream
python -m personafactory.downstream.seeds --release swiss-ai/PersonaFactory --setting language_matched \
    --seed-shards "$PF_DATA_DIR/seeds/*.jsonl" --out $W/seeds_language_matched.jsonl
python -m personafactory.downstream.seeds --release swiss-ai/PersonaFactory --setting cross_lingual \
    --seed-shards "$PF_DATA_DIR/seeds/*.jsonl" --out $W/seeds_cross_lingual.jsonl
```

### 2. Arms A0 and A1 (`build_arms.py`)

Samples 100,000 language-matched conversations (fixed seed) after holding out 5% of all persona ids (fixed hash of the
persona id) and dropping malformed conversations, turn-count mismatches with the seed, more than 24,000 characters or
more than 3,800 tokens.

```bash
python -m personafactory.downstream.build_arms --release swiss-ai/PersonaFactory --seeds $W/seeds_language_matched.jsonl \
    --tokenizer $PF_MODEL_DIR/Apertus-v1.5-8B --work $W
```

Outputs: `$W/data/{A0,A1}_source.jsonl`, `heldout_personas.json`, `manifest.json`. Source records have the Megatron
prepare schema `{id, family_id, language, response_mode, training_role, messages}`.

### 3. Arm A0r and arm X1 (`a0r.py`, `x_arms.py`, shared `regen.py`)

Regeneration through the pipeline's own conversation loop (`augmentation.pipeline.process_conversation`) with fixed
user turns: the released responder of each conversation (Gemma 4 31B or Ministral 3 14B), no persona system prompt,
no model persona, next-turn continuity loop and MiniMax-M2.5 sanity gate. X1 first translates every seed user turn
with `augmentation.pipeline.translate_turn` (Gemma, temperature 0.3, protected spans, LID check with `PF_LID_MODEL`).
Endpoints as in `scripts/slurm/serve_models.sh`; one 2-node unit (Gemma + Ministral, MiniMax-M2.5) per array task
of `scripts/slurm/downstream_regen.sbatch`. Resumable by id.

```bash
python -m personafactory.downstream.a0r build --work $W --release swiss-ai/PersonaFactory
python -m personafactory.downstream.a0r run --work $W --gemma $GEMMA_URL --ministral $MINISTRAL_URL --minimax $JUDGE_URL
python -m personafactory.downstream.x_arms build --work $W --release swiss-ai/PersonaFactory \
    --seeds $W/seeds_cross_lingual.jsonl --tokenizer $PF_MODEL_DIR/Apertus-v1.5-8B --n 50000
python -m personafactory.downstream.x_arms run --work $W --gemma $GEMMA_URL --ministral $MINISTRAL_URL --minimax $JUDGE_URL
```

### 4. Shared id sets (`assemble_arms.py`, `x_arms.py assemble`)

```bash
python -m personafactory.downstream.assemble_arms --work $W --tokenizer $PF_MODEL_DIR/Apertus-v1.5-8B   # -> $W/data_paired/
python -m personafactory.downstream.x_arms assemble --work $W --tokenizer $PF_MODEL_DIR/Apertus-v1.5-8B  # -> $W/data_x/
```

The manifests report the per-arm median assistant-turn length (paper: A0 and A1 1,131 characters, A0r 2,618, A2 956).

### 5. Fine-tuning (`megatron/`, Megatron-LM)

Recipe: `Apertus-v1.5-8B` base, full multi-turn conversations with loss on every assistant turn, one epoch,
sequence length 4,096 with best-fit-decreasing packing (at most 8 documents per sequence), global batch 128, micro
batch 1, tensor parallel 4 on 4 nodes x 4 GPUs, learning rate 1e-5 decayed to 1e-6 with a cosine schedule after 3%
warmup, weight decay 0, gradient clipping 1.0, bf16. Training seeds: 1234, 2 and 3 for A0, A1 and A2; 1234 for A0r,
X1 and X2. Validation: 1% family-level split (3% for X1 / X2), evaluated once at the end. The final checkpoint is
exported to Hugging Face format.

| File | Purpose |
|---|---|
| `megatron/tokenizer_view.py` | run-local tokenizer view with the assistant-begin / assistant-end markers (ids 67 / 68) |
| `megatron/render_config.py`, `megatron/apertus_v15_8b_sft.json` | per-arm run config (architecture, tokenization, hyperparameters, pinned source sha256) |
| `megatron/prepare_dataset.py` | chat-template rendering and IndexedDataset `.bin/.idx` per split, assistant regions validated |
| `megatron/plan.py` | one-epoch packed budget (`training_plan.env`: TRAIN_SAMPLES, TRAIN_ITERS, ...) |

Slurm: `downstream_megatron_setup.sbatch` once (tokenizer view and Hugging Face -> Megatron TP4 conversion of the
base checkpoint), then `downstream_megatron_pipeline.sh` per arm (prepare -> pack -> 1-node smoke run -> training per
seed -> export per seed):

```bash
export WORK_ROOT=$W/sft MEGATRON_ROOT=/path/to/Megatron-LM TRANSFORMERS_ROOT=/path/to/transformers HF_SAVER=<Apertus HF saver>
BASE_MODEL=... TOKENIZER_SOURCE=... TEMPLATE_SOURCE=... sbatch scripts/slurm/downstream_megatron_setup.sbatch
ARM=A2 SOURCE=$W/data_paired/A2_source.jsonl EXPORT_PREFIX=$PF_MODEL_DIR/Apertus-v1.5-8B-base-PF SEEDS="1234 2 3" \
    bash scripts/slurm/downstream_megatron_pipeline.sh
```

Requirements: a Megatron-LM checkout with Apertus support (`--ap-sft` packing, xIELU, Apertus checkpoint loader and
Hugging Face saver; commit pinned in `apertus_v15_8b_sft.json`) and a matching transformers checkout. The base model
is the text-only view of `swiss-ai/Apertus-v1.5-8B-base` (input embedding cut to the 131,072 text rows, matching the
131,072-row output head) with its tokenizer trimmed to the same ids (`BASE_MODEL`, `TOKENIZER_SOURCE`); the chat
template comes from `swiss-ai/Apertus-v1.5-8B` (`TEMPLATE_SOURCE`). The exports are text views as well and are
served with stock vLLM.

### 6. Evaluation (`eval/`)

Prompts (once, `--data-dir $E`, e.g. `E=$PF_DATA_DIR/downstream_eval`):

```bash
python -m personafactory.downstream.eval.fetch_benchmarks --data-dir $E          # IFEval, GSM8K, MBPP sanitized, MMLU, ARC-Challenge
python -m personafactory.downstream.eval.perturb_rules --data-dir $E             # -> styled.jsonl
python -m personafactory.downstream.eval.perturb_persona --data-dir $E --heldout $W/data/heldout_personas.json \
    --bank $PF_BANK --urls $GEMMA_URL --model gemma --k 3                         # -> styled_persona.jsonl
python -m personafactory.downstream.eval.intent_check prep --data-dir $E
python -m personafactory.downstream.eval.judge_client --shards $E/intent_items/000.jsonl --outdir $E/intent_results \
    --urls $JUDGE_URL --model MiniMax-M2.5 --max-tokens 2048
python -m personafactory.downstream.eval.wildchat_prompts --data-dir $E --train $W/data/A0_source.jsonl  # -> wildchat.jsonl
python -m personafactory.downstream.eval.intent_check merge --data-dir $E         # -> styled_all.jsonl
```

- Rule-based perturbations (`perturb_rules.py`, deterministic): `lower`, `nopunct`, `typo3`, `typo8`, `abbrev`, `terse`,
  `messy` (lower + nopunct + typo3 + abbrev) of IFEval, GSM8K and MBPP; IFEval string arguments, quotes, code, URLs
  and numbers are protected, and IFEval items that lose a required string are dropped.
- Persona perturbations (`perturb_persona.py`): each prompt rewritten by 3 held-out English-speaking personas with the
  pipeline's user rewrite template (Gemma-4-31B, temperature 0.7, quirk probability 0.25, literal protection), kept
  only if MiniMax-M2.5 confirms with the intent template that the task is unchanged (`intent_check.py`; 99.6% in
  the paper).
- WildChat prompts (`wildchat_prompts.py`): 500 English and 500 other-language messy first user turns from WildChat
  conversations no arm was trained on, with PII, URL, unsafe-term and copied-boilerplate filters.

Per fine-tuned model (`scripts/slurm/downstream_eval_generate.sbatch`: one vLLM replica per GPU, greedy, thinking
disabled):

```bash
python -m personafactory.downstream.eval.gen_eval --urls $URLS --data $E/styled_all.jsonl --out $R/A2
python -m personafactory.downstream.eval.score --data $E/styled_all.jsonl --out $R/A2
```

Clean capability with upstream lm-evaluation-harness (`pip install "lm_eval[vllm]"`; tasks in
`eval/lm_eval_tasks.txt`, Slurm: `scripts/slurm/downstream_lm_eval.sbatch`):

```bash
lm_eval --model vllm --model_args pretrained=$MODEL,tensor_parallel_size=1,data_parallel_size=4,gpu_memory_utilization=0.75,enable_thinking=False \
    --tasks mmlu_flan_cot_zeroshot,arc_challenge_chat,gsm8k_cot,ifeval,mbpp_instruct \
    --apply_chat_template --fewshot_as_multiturn --gen_kwargs max_gen_toks=2048 --batch_size auto \
    --confirm_run_unsafe_code --log_samples --output_path $PF_OUT_DIR/downstream/lm_eval/A2
```

Reported metrics: MMLU `exact_match` (ordered extraction), ARC-C `exact_match`, GSM8K `exact_match`, IFEval
`prompt_level_strict_acc` and `prompt_level_loose_acc`, MBPP `pass_at_1`. The cross-lingual arms add `multi-if`,
`mgsm_en_cot`, `global_mmlu_gen_0shot` and `include_base_44_gen_0shot` (INCLUDE, 44 languages); task names follow the
harness version used for the paper and may differ in other versions. `enable_thinking` is passed to the chat template;
drop it if your harness version does not accept it.

Reports:

```bash
python -m personafactory.downstream.eval.report --results-dir $R --models A0 A1 A0r A2 --compare A1:A0 A2:A0r A2:A1 A2:A0
# WildChat pairwise: two external judges (Qwen3.6-35B-A3B, Muse-Glimmer-30B), both presentation orders
python -m personafactory.downstream.eval.wildchat_pairwise prep --data-dir $E --results-dir $R --pairs A2:A0r A2:A1 A2:A0
python -m personafactory.downstream.eval.judge_client --shards $E/wc_items/all.jsonl --outdir $E/wc_results_qwen36 \
    --urls $QWEN_URL --model qwen --max-tokens 8192 --concurrency 256          # same for muse -> wc_results_muse
python -m personafactory.downstream.eval.wildchat_pairwise agg --data-dir $E --results-dir $R --judges qwen36 muse
```

- `report.py`: clean score, robustness gap (clean minus perturbed) per perturbation and pooled, for rule-based and
  persona variants, and paired differences between arms, all with 95% paired bootstrap intervals over items
  (10,000 resamples). Positive gap difference: the first arm loses more.
- `wildchat_pairwise.py`: a win needs the same pick in both orders; the length-controlled win rate is the intercept of a
  logistic regression of the per-order verdict on log(length X / length Y), i.e. the win rate at equal length, with a
  95% bootstrap interval over prompts.

Pairs take a list such as `A2:A0r,A2:A1`. Pass it as arguments, a file (`--pairs-file`) or the `PAIRS` environment
variable set before `sbatch`; never via `sbatch --export=...,PAIRS=a:b,c:d`, which splits its argument on commas.

## Differences from the paper runs

- The paper sampled from the corpus' internal training split (a seed-disjoint split that is not part of the published
  dataset, which has a single `train` split); `build_arms.py` samples from all language-matched conversations
  (`--exclude-ids` leaves out any ids you want to keep for evaluation).
- The WildChat evaluation prompts were drawn from the pipeline's WildChat seed pool of the cross-lingual setting;
  `wildchat_prompts.py` draws them from WildChat conversations that are not seeds of any language-matched released
  conversation, with the same filters (or from the seed records, `--seed-shards`).

Dependencies: `aiohttp`, `numpy`, `pyarrow`, `datasets`, `tokenizers`, `transformers`, `matplotlib`; `lm_eval` (IFEval
checkers in `score.py` and the clean benchmarks); vLLM for serving; Megatron-LM with Apertus support for training.
